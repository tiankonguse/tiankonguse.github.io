## 2. Front matter 规范

- `title`：`leetcode 周赛 NNN`（NNN 为场次号）。
- `description`：一句话点出本场最核心考点（参考上一篇）。
- `updateDate`：比赛当天时间，格式 `YYYY-MM-DD HH:MM:SS`。
- 其余字段固定不变。
- 注意：front matter 每个字段行尾有两个空格（硬换行），与正文一致。

## 3. 每题节内结构

1. **题意**：用自己的话完整重述题目背景与问题，保留关键约束与边界条件（如左闭右开、环形、最多一次等）；不得只写一两句话带过。示例可省略，但关键定义不可省略。
2. **数据范围（强制）**：题意之后必须单独一行列出数据范围，格式为 `数据范围：...`，包含所有变量的上下界、部分得分数据的特殊条件（如"30% 的数据满足 k ≤ 4"）。从题目 .md 的「数据范围」或「说明/提示」节提取，不得遗漏。
2. **单解法**：`思路：XXX` 单独成行。随后给出推导（核心观察 → 状态定义/算法步骤 → 复杂度 `O(...)`），再附代码。
3. **多解法（强制）**：同一题存在多个正确解法时，必须全部介绍。用 `### 解法一：XXX`、`### 解法二：XXX` 三级标题分节，按由浅入深或得分由低到高排列；每种解法独立包含思路、复杂度、代码块。推荐解法在标题标注「（推荐）」。
4. **错误/部分得分解法（强制）**：目录中存在的失败版本（WA、部分得分、错误重写）必须介绍。用 `### 错误解法：XXX` 或 `### 解法一：XXX（20 分）` 标题，说明思路、附关键代码、明确分析失败原因（数据范围溢出、循环太长超时、答案变量溢出、死循环、重复输出等）。部分得分版本要写清「为什么只有 X 分」。
5. **代码**：给出与思路对应的核心代码片段。片段应尽量自洽（引用的变量/函数给出定义），但不要求贴完整类框架。

## 4. 推导类内容的写作规范（重点）

- **双向等价**：凡是写「X 等价于 Y」的结论，必须给两个方向的证明，各写一段。
- **正方向**：按定义结构做递归拆分或归纳。例（好字符串 ⟹ 每块长度为奇数）：沿条件二递归拆分 s，因长度严格递减必然终止，最终拆成若干个条件一字符串；每层拼接处两侧字符不同，子串不合并，故每块长度都是奇数。
- **反方向**：按规模做归纳（如块数）。写清归纳基础与归纳步。
- **措辞精确**：结论的限定词要准确。如「每个相同字符连续块的长度都是奇数」≠「整个字符串的长度是奇数」——必要时用反例澄清（"ab" 是好字符串但长度为 2），避免读者混淆。
- **可复算**：递推公式给出初始值；矩阵/递推结果可用小 n 验证（如 f(1)=2, f(2)=2, f(3)=4, f(4)=6）。

## 5. 排版规范

- 中文正文；行尾两个空格（硬换行）断句；段落之间空一行。
- **题意排版（强制）**：题意中每句话单独占一行（行尾两空格硬换行），不得多句话挤在同一行；题意段落与数据范围段落之间空两行（两个空行）。数据范围同理每句一行。
- 代码块统一 ` ```cpp `，代码内 2 空格缩进；关键行可加中文注释。
- 内联代码/变量用反引号。
- 数字、复杂度、题名与原文一致；不自行编造题目链接。
